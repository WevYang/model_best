# Benchmark 数据来源与评测集说明

## 1. 总览结论

- 幻觉 benchmark 通常不是“单一 COCO2017”。POPE/CHAIR 更依赖带对象标注的图像集合与评测配置；HallusionBench、MMHal-Bench、AMBER、FaithScore 则各有独立构造口径。
- POPE 常基于带 object annotation 的图像数据构建，原论文在 MSCOCO validation 上评测，也展示了 SEEM-based POPE 可扩展到 A-OKVQA / GQA。仅凭模型报告写“POPE”不能判断 COCO2014、COCO2017 或其它底层数据。
- MMHal-Bench 原论文明确使用 OpenImages validation/test 图像，并围绕 COCO 12 个对象大类设计 96 个 image-question pairs。
- HallusionBench 是 curated / human-crafted image-context reasoning benchmark，包含原图、人工编辑图和 control pairs，不是 COCO/OpenImages 的简单子集。
- OCRBench / OCRBench-v2 聚合 OCR、scene text、document、chart、KIE、HMER 等多个来源；DocVQA、ChartQA、TextVQA、InfoVQA 本身就是下游 proxy 数据集。
- 模型技术报告多数只写 benchmark 名和得分，通常不写底层 source dataset / split / prompt template；要复现需要回到 benchmark 原论文、GitHub/HF 或 lmms-eval/OpenCompass 配置。

## 6. 复现注意事项

- 复现 POPE 时必须固定底层数据集、对象标注来源、positive/negative 比例、random/popular/adversarial 设置和 prompt template。
- 复现 CHAIR/ObjHalBench 时必须固定 caption 生成协议、COCO object vocabulary、同义词映射和 caption parsing 方法。
- 复现 HallusionBench/MMHal-Bench/AMBER/FaithScore 时优先使用官方 release；不要从模型报告表格反推样本。
- 复现 OCR/document/chart/video proxy 时必须明确官方 split、是否使用 hidden test、是否使用 subtitles/audio、以及是否有 LLM judge。
- 报告中建议写出 dataset version、split、sample size、prompt template、judge model 和 metric direction。
